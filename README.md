# CodeArena

Programming challenge platform: browse problems by difficulty and topic, write a solution in the browser, submit it for automated judging, and track progress on a leaderboard. Next.js + Tailwind frontend, Java Spring Boot API, PostgreSQL.

## Features
- 9 bundled problems (easy / medium / hard) with topics, statements and sample tests; filter by difficulty, topic and title.
- In-browser CodeMirror editor with language selection and starter code; **Run samples** (not recorded) and **Submit** (judged on all tests, recorded).
- Verdicts: Accepted, Wrong answer, Runtime error, Compile error, Time limit, Memory limit, Runner error. Visible-test failures show input, expected and actual output; **hidden tests never reveal their data**.
- Accounts, submission history per problem, personal progress by difficulty, and a leaderboard (easy 10 / medium 20 / hard 30 points, ties go to the earlier finisher).

## How code is executed (read this)
Solutions are **functions** (e.g. `function twoSum(nums, target) { ... }`) that return their answer; test inputs and expected outputs are JSON. Submitted code is **never run inside the API process**. Execution sits behind one interface, `CodeRunner` (`exec/Exec.java`), with two adapters chosen by `EXECUTION_ADAPTER`:

| Adapter | Languages | Isolation | Status |
|---|---|---|---|
| `local-js` (default) | JavaScript | Each submission runs in its own short-lived JVM (`JsWorker`) hosting a **GraalJS** context with no file, network, thread, process, native, environment or Java access. Limits: heap (`-Xmx`), JavaScript statements per test, wall-clock time (process is killed), stdout size, empty working directory and empty environment. | Implemented and tested here, including attempts to read files, call Java, spawn processes, fetch URLs and loop forever. |
| `judge0` | JavaScript, Python | A self-hosted [Judge0 CE](https://github.com/judge0/judge0) service (containers with CPU/memory/time/network limits). | Implemented against Judge0's documented API and tested **only against a stub server**: no container runtime was available here, so it has never run against a real Judge0. Check language ids with your instance's `/languages` and test before relying on it. |

The local adapter is a strong guard for a demo, class or internal tool, but a Java process is not a hardened container. **For untrusted public traffic use a container- or VM-based judge** (the `judge0` adapter or your own implementation of `CodeRunner`). The platform is deliberately honest about this: with the default adapter only JavaScript is offered.

## Architecture
```
Next.js (frontend/) ──/api rewrite──▶ Spring Boot (backend/) ──▶ PostgreSQL (Flyway)
                                         └─ CodeRunner ──▶ local GraalJS worker process | Judge0
```
Problems and tests are generated by `tools/gen-problems.mjs`: expected outputs come from reference solutions, so they cannot disagree with them. `backend/src/main/resources/problems.json` is loaded on first start.

## Security
BCrypt passwords, random session tokens stored hashed (HttpOnly, SameSite=Lax cookie), Origin check on state-changing requests, login/register throttling, code size limit, one run at a time per user with a short cooldown, bounded concurrent executions, no hidden test data in any response.

## Run
Prerequisites: JDK 21+ (tested on 27), Node 20+, PostgreSQL 14+.
```bash
createdb codearena
cd backend && cp .env.example .env     # set DB_* if needed
./mvnw spring-boot:run                 # API on :8080, migrations and problems load on start
cd ../frontend && cp .env.example .env.local
npm install && npm run dev             # http://localhost:3000
```
Regenerate the problems: `node tools/gen-problems.mjs`.

## Tests
`cd backend && ./mvnw test -Dtest='LocalJsRunnerTest,ReferenceSolutionsIT,Judge0RunnerTest'` needs no database. `./mvnw test -Dtest=ApiIT` needs PostgreSQL (`codearena_test`, default `localhost:5434`; override with `TEST_DB_URL`, `TEST_DB_USER`, `TEST_DB_PASSWORD`). Together (23 tests): sandbox behaviour and escape attempts; every bundled problem is solvable by its reference solution through the real sandbox and an exponential solution is rejected; the Judge0 adapter against a stub; and the API workflow (auth, filters, hidden-test secrecy, verdicts, progress, leaderboard, throttling). Each sandboxed run starts a JVM, so the suite takes a few minutes.

## Limits
Local runner supports JavaScript only and a submission takes a few seconds (JVM start). Problems are function-style, not stdin/stdout programs. No admin UI for adding problems (edit `tools/gen-problems.mjs`).
